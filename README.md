
# NEW_GAME (a.k.a. GOTY)

A 2D top-down dungeon crawler built in **C++** with the **Qt** framework (Qt Widgets, Qt Graphics View, and Qt Multimedia). You explore a tile-based maze, fight off waves of enemies, dodge hazards, and take down a final boss.

## 📖 About

This project was built as a course/team project using the Qt framework and the Qt Graphics View system for rendering. The game features:

- A 30x30 tile-based map loaded from a text file (`Board.txt`), with custom tile types for walls, hazards, doors, and passable-only-by-enemy walls.
- A player character with directional movement, shooting, and health.
- Multiple enemy types (`minor`, `major`, `boss`) with different stats and behavior.
- An **A\* pathfinding** implementation (`a_star.cpp` / `a_star.h`) used for enemy movement/AI.
- Projectiles fired by the player to defeat enemies.
- Collectible coins.
- Timed doors (`doortimer`).
- A main menu (`main_menu`) built with Qt Designer `.ui` files.
- Background music and sound effects via `QMediaPlayer` (`.mp3` assets, `sound.qrc`).
- Custom sprites/tilesets (`.png` assets, `res.qrc`) — Minecraft/Nether-themed tiles (Netherrack, Soul Sand, Lava, etc.) alongside custom character sprites.

## 🗺️ Map Legend

The map is defined in `Board.txt` as a grid of integers. Special tile values:

| Value | Meaning |
|---|---|
| `-1` | Hazard / death zone (e.g. lava — instant kill on contact) |
| `-2` | Door |
| `-3` | Passable wall (enemies of type "major" can pass through) |
| `-4` | Static wall |
| `0` or above | Normal floor tile |

## 🧱 Project Structure

```
GOTY(18-4-22)/          # Main Qt project (source of truth)
├── GOTY.pro            # Qt project file
├── main.cpp            # Entry point — sets up the scene, map, player, and enemies
├── mainwindow.*         # Main game window
├── main_menu.*          # Main menu UI
├── character.*          # Base class for all characters (player + enemies)
├── player.*             # Player-specific logic (input handling, shooting)
├── enemy.*, minor.*, major.*, boss.*  # Enemy types and AI
├── entity.*             # Shared entity behavior
├── projectile.*         # Player projectiles
├── coin.*               # Collectible coins
├── doortimer.*          # Timed door logic
├── a_star.*             # A* pathfinding used by enemy AI
├── res.qrc / sound.qrc  # Qt resource files bundling images and audio
└── *.png, *.mp3         # Game art and audio assets
```

> **Note:** The repository also contains several `build-GOTY-*` directories generated by Qt Creator (compiled binaries, object files, and IDE caches). These are build artifacts, not source code, and can safely be deleted or ignored — see [Housekeeping](#-housekeeping) below.

## 🛠️ Requirements

- **Qt 5** (developed against Qt 5.14.2; Qt 5.12+ should work) with the following modules:
  - `QtCore`, `QtGui`, `QtWidgets`
  - `QtMultimedia` (for audio playback)
- A C++11-compatible compiler (MSVC, MinGW, or GCC/Clang on Linux/macOS)
- [Qt Creator](https://www.qt.io/product/development-tools) (recommended) or `qmake` + your preferred build tool

## 🚀 Building & Running

### Option 1: Qt Creator (recommended)
1. Open Qt Creator.
2. Open `GOTY(18-4-22)/GOTY.pro`.
3. Select a configured Qt kit (Desktop Qt 5.14.2 or similar).
4. Build and run (`Ctrl+R` / `Cmd+R`).

### Option 2: Command line with `qmake`
```bash
cd "GOTY(18-4-22)"
qmake GOTY.pro
make        # or mingw32-make on Windows with MinGW
```
Then run the resulting executable (e.g. `./GOTY` or `GOTY.exe`).

> **Important:** Run the executable from the `GOTY(18-4-22)` directory (or ensure `Board.txt` and the image/audio assets are alongside it), since assets are loaded via relative paths at runtime.

## 🧹 Housekeeping

A few suggestions if you plan to keep developing this project:
- Add a `.gitignore` for Qt Creator build directories (`build-*/`), `*.pro.user*`, and compiled objects (`*.o`, `*.exe`) so the repo stays lean.
- Consider consolidating the older loose files at the repo root (`enemy.cpp`, `minor.cpp`, `Model/`, `Projectile dump/`, `*.zip`) into the main `GOTY(18-4-22)` project, or removing them if they're superseded, to avoid confusion about which files are the current source of truth.
